## What are Scrum artifacts and events? Explain how the Product Backlog, Sprint Backlog, Increment, Sprint, Daily Scrum, Sprint Review, and Sprint Retrospective contribute to a project.

Product Backlog is the prioritized list of all the features, bug fixes and improvements that need to be made to the product. Sprint Backlog is the list from product backlog that needs to be completed during a sprint. Increment is the collection of all completed backlogs during a sprint, representing the current state of the project. Sprint is a time-boxed iteration which normally lasts for 2-4 weeks during which team works on a specific tasks from the sprint backlog. Daily Scrum is a short, daily meeting between the team members where they discuss the task they did, what the further plans are and if there is any obstacles. Sprint review is a meeting held at the end of the sprint where the team demonstrates the work completed to the stakeholders. Sprint retrospective is a meeting where the team reflects on the sprint and discusses ways to improve in the next iteration

## What is Feature-Driven Development (FDD)? Explain its main features and describe how FDD organizes software development around features.

**FDD** is an agile software development methodology that focuses on delivering tangible, working software features within short iterations. Its main features include:
- Domain object modeling which serves as a basis for the system design, by modeling the key entities, their attributes and relationships
- Developing by feature, where features are small and the system is developed by building a series of these features
- Short iterations, where development is broken into short cycles, allowing for regular and timely delivery of software
- Feature teams, which include small cross-functional teams which focus on developing features
- Design and build by feature, where each feature goes through a design and build phase, ensuring that it is fully implemented and integrated
- Regular builds, where frequent integration and builds are done to ensure that the software is always working in a working state
- Best practices, which emphasize the use of industry, best practices such as version control, code inspections, and unit testing.
**FDD** organizes software development around features by focusing on small features that are useful to the customer. First, the team makes an overall model and a list of features. Then they plan, design, and build each feature. For example, in an online shop, features can be login, product search, shopping cart, and payment.
